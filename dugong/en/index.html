PRODUCT INTENT

A coach for safer work improvement, not a surveillance tool for AI use.

Dugong records work-use cases across AI tools such as ChatGPT, Claude, Gemini, and Copilot. It analyzes task type, purpose, prompting pattern, failure cause, security risk, and outcome signals. The output is retained as evidence for better prompts and team learning topics, not as a score for individual evaluation.

01

Local-first protection

Raw prompts, chat history, result text, and direct identifiers are excluded from central anonymous telemetry.

02

Diagnosis separated from display

JavaFX collects and presents; Python owns analysis, security judgement, persistence, export, and audit contracts.

03

Reviewed learning evidence

AI-suggested values are not learning labels. User-confirmed, corrected, or human-reviewed values are the valid candidates.

PRODUCT EVIDENCE

Prompt capture, diagnosis, reporting, and coaching in one work flow.

The active product interface is a JavaFX desktop application. Its start screen frames the entry flow from recording a case, through diagnosis, to an improvement direction and a report.

The public screen shows only the product start experience and feature flow. No employee case, raw prompt, organization, or identifier is included.

GOVERNED LEARNING

Raw-text blocking and human review come before any learning dataset.

Dugong puts the user's control over the data path first. Anonymous telemetry and local learning data are separate, and high-risk cases preserve an expert-review requirement.

  1. Raw-text protection

    Sensitive prompts and results do not enter central telemetry.

    Only usage patterns and safe metrics remain in central telemetry. Raw text and direct identifiers are governed separately.

    Telemetry policy and payload-guard tests verify the outbound boundary.

  2. Case diagnosis

    Task type, purpose, prompting pattern, failure cause, and risk return through a defined contract.

    The UI does not calculate the analysis directly. Python services and a CLI JSON contract return a consistent result shape.

    Separating UI from the analysis core contains the regression surface.

  3. Human feedback

    User confirmation and correction take precedence over an automated diagnosis.

    Source and confidence stay with confirmed, corrected, and reviewed labels so later decisions can be audited.

    AI-suggested values cannot be promoted directly to confirmed training labels.

  4. Quality gate

    Incomplete or risky rows are excluded from learning export and retained with their reason.

    Label source, confidence, redaction, required context, and post-use leakage are checked before CSV and JSONL preparation.

    Rejected rows are evidence for improving collection quality, not silent data loss.

ML READINESS

Model training is not a completed feature. It opens only when its gates are satisfied.

Rule-based diagnosis remains the valid baseline. Baseline models, hyperparameter optimization, and model promotion are considered only after enough human-confirmed labels, class balance, group diversity, no post-use leakage, and high-risk review are verified.
