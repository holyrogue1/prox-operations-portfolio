현장 데이터가 숫자에 도달하는 과정을 다시 설계하다

공사 현장에서는 수주 정보, 자재 출고, 시공비, 직불 경비, 지급수수료가 서로 다른 입력 흐름에서 발생합니다. 프록스는 이 정보를 프로젝트와 품목 단위로 연결해 현장관리대장과 영업 마감자료가 같은 근거를 바라보도록 구성했습니다.

01

업무 데이터의 보존

기존 업무 컬럼과 원본 엑셀 증거를 유지하고, 정규화와 보정은 이력으로 쌓습니다.

02

권한을 갖는 검토

수정과 매칭 결정은 역할별 권한을 거치며, 승인 주체와 시점을 남깁니다.

03

현장 기준의 대사

수익률은 숫자를 나열하는 대신 실제 실행원가와 대조 가능한 구조로 계산합니다.

제품 증적

로그인 다음에는, 현장 운영의 전체 흐름이 있습니다.

프록스는 알림과 일정, 수주, 시공·기타비, 분석 데이터를 하나의 업무 흐름으로 다룹니다. 아래 화면은 실제 제품에서 캡처한 뒤 공개 범위를 위해 데이터 셀만 비식별 처리했습니다.

메뉴 구조와 표의 컬럼, 조회와 처리 흐름은 실제 화면 그대로입니다. 고객명, 담당자, 계약금액 등 운영 데이터는 공개 포트폴리오에서 노출하지 않습니다.

수익률의 차이를 계산식이 아니라 데이터 흐름에서 찾다

영업 마감자료의 집행수익률과 현장관리대장의 실제 수익률이 달라지는 현상을 운영 데이터로 대조했습니다. 원인은 수량만 기록된 제품출고가 마감 엑셀에서 실행자재비 0원으로 처리되던 흐름이었습니다.

엑셀 산출 원칙

실행 내역이 있는 품목의 실행자재비는 품의 자재비를 기본값으로 참조하고, 사용자는 엑셀에서 값을 조정할 수 있습니다. 집행수익률은 그 변경을 수식으로 즉시 반영합니다.

실제 작업 과정

문제를 수정하는 데서 멈추지 않고, 다음에도 같은 숫자가 나오게 했습니다.

프록스의 작업은 현장의 요청을 화면에 반영하는 것에서 끝나지 않습니다. 데이터가 왜 달라졌는지 확인하고, 원본을 보존한 채 계산 규칙과 검증 이력을 남겨 다음 마감에도 재현할 수 있게 만듭니다.

  1. 발견

    출고 내역은 있는데 실행자재비가 0원으로 계산되고 있었습니다.

    제품출고 수량이 등록된 항목이 마감 엑셀의 실행자재비 산식에 충분히 반영되지 않아 집행수익률이 실제보다 낮아졌습니다.

    출고, 현장관리대장, 영업 마감자료를 같은 프로젝트 기준으로 대조했습니다.

  2. 대조

    현장관리대장과 마감자료의 수익률 차이를 프로젝트별로 분리했습니다.

    진행 중인 4개 프로젝트를 비교해, 수정 전에는 26.01~39.51%p의 괴리가 있음을 확인했습니다.

    차이를 단순 표시하지 않고 자재비, 시공비, 직불비, 수수료의 계산 경로를 각각 확인했습니다.

  3. 규칙 고정

    실행 내역이 있으면 실행자재비는 품의 자재비를 기본값으로 참조하게 했습니다.

    현장 사용자는 기존처럼 엑셀에서 값을 조정할 수 있고, 조정값은 집행수익률 산식에 즉시 반영됩니다.

    업무 컬럼을 바꾸지 않고 마감 산출 서비스의 참조 규칙을 보완했습니다.

  4. 재검증

    수정 후 프로젝트 소계 기준의 괴리를 0~0.19%p까지 줄였습니다.

    이 값은 현장관리대장과 동일한 비용 기준으로 다시 계산한 결과이며, 원본 출고 내역을 덮어쓰지 않습니다.

    산식의 변경과 기존 입력 데이터의 보존을 분리해, 결과와 근거를 함께 추적할 수 있게 했습니다.

  5. 확장 준비

    보정과 검토의 이력을 다음 후보 매칭과 이상탐지의 근거로 축적합니다.

    정규화, 후보 제시, 검토자 승인·보정·반려, 피드백 보관을 분리해 ML이 업무 판단을 대신하지 않도록 했습니다.

    원본과 파생값, 승인 결정은 별도로 보관하며 재무 데이터는 사람의 승인 없이는 바뀌지 않습니다.

이 과정의 핵심은 한 번의 수치 보정이 아니라, 같은 종류의 오류가 다시 들어와도 발견·대조·검증할 수 있는 운영 규칙을 남기는 것입니다.

프록스 고도화 제안

측정, 기준, 실적, 자동화의 순서를 지키는 것이 가장 효율적입니다.

프록스는 ERP나 MES를 한 번에 교체하는 계획보다, 현재 운영 데이터의 신뢰도를 단계별로 올리는 방법을 권고합니다. 앞 단계의 검증이 부족하면 다음 투자도 보류합니다.

  1. 4주

    실측

    처리시간, 승인대기, 재작업, 입력시간, 기록완료율의 기준선을 한 조직에서 확인합니다.

  2. 6개월

    기준

    프로젝트, 자재, 규격, 단위, 단가 기준일과 최종 REV를 검증·승인합니다.

  3. 12개월

    실적

    출고, 반납, 현장잔량, 폐기 사유를 남겨 실제원가와 표준 차이를 설명할 수 있게 합니다.

  4. 24개월

    자동화 판단

    A등급 승인 데이터가 쌓였을 때에만 추천과 이상탐지 등 ML 보조 기능을 확대합니다.

프록스 현재

프로젝트 기준의 대사와 감사 가능성

원본 보존, 법인·프로젝트 식별, 마감 수익률 대사, 검토 이력을 통해 숫자의 근거를 남깁니다.

Gate A·B 이후

현장 실적의 최소기록과 기준정보 검증

자재 출고부터 반납·잔량·폐기까지의 사건 기록을 마감과 연결해 실제원가 산식의 공백을 줄입니다.

Gate C 이후

승인 데이터를 쓰는 ML 보조

후보 매칭과 이상징후 탐지는 검토자를 보조하며, 업무·재무 데이터의 자동 변경이나 자동 승인은 하지 않습니다.

권고 운영 모델은 기존 AX·IT·ML 담당자가 구조를 맡고, 도면·BOM 및 단가·원가 검증 역할을 먼저 분리한 뒤 6개월 Gate에서 DataOps·MES 운영 역할을 추가 판단하는 방식입니다. 인력과 예산은 4주 실측 결과로 재산정해야 하며, 보고서의 시나리오를 확정치로 사용하지 않습니다.

자동 승인보다 먼저, 학습 가능한 근거를 만든다

프록스의 ML 영역은 모델을 성급히 운영하는 대신 데이터 계보와 검토자 결정을 먼저 구축합니다. 자동 학습, 자동 점수화, 자동 승인은 이 단계의 범위에 포함하지 않습니다.

  1. M1

    원본 스테이징

    수입 파일과 원본 참조를 변경하지 않는 증거로 보관합니다.

  2. M2

    정규화

    텍스트와 단위를 규칙 버전 및 변환 이력과 함께 정리합니다.

  3. M3

    후보 매칭

    결정론적 후보와 근거를 제시하되 업무 데이터를 자동 변경하지 않습니다.

  4. M4

    품질 격리

    신뢰하기 어려운 원본 행은 일반 처리 흐름에서 분리합니다.

  5. M5

    피드백 준비

    승인, 보정, 반려 결정을 불변 피처 스냅샷과 함께 축적합니다.

Reviewer Gate 실제 품목 식별과 업무 변경은 검토자 결정 이후에만 이뤄집니다.

Audit Trail 후보, 근거, 검토 이력, 피드백 레이블을 분리해 추적합니다.

코드 증적

추천을 시작하는 코드보다, 멈춰야 할 조건을 먼저 적었습니다.

실제 training_gate.py는 사람의 검토 레이블과 검토 기간을 확인하고, 조건이 부족하면 학습 시작 상태를 항상 거짓으로 남깁니다. 모델 실행은 이 보고서만으로 시작되지 않습니다.
